# 网文 AI 痕迹检测

> 检测中文网文的 AI 含量，并**逐条列出判定原因**——不是只丢给你一个分数。

**网页版：<https://xieshougulishi.github.io/webnovel-ai-detector/>**　·　**Skill：[skill/](skill/)**（可装进 Claude Code、DSH 等）

一个可解释的 AI 痕迹检测工具。对比"朱雀"这类黑箱检测器：它给你一个 87% 就结束了，而这个工具会告诉你**哪一条命中、落在原文第几个字、实测值和人类基线差多少、为什么算异常、具体怎么改**。

计分公式与词表全部公开，每条判定都能复核。

---

## 看它能给出什么

| 输出 | 说明 |
|---|---|
| **AI 含量风险分 + 不确定区间** | 五档（极低/偏低/中等/偏高/极高），附带因证据分散度而变宽的区间，不假装精确 |
| **命中哪几条特征** | 精确定位到原文的字符位置，可直接跳过去看 |
| **实测值 vs 人类基线** | 说明"为什么这条算异常"，而不是凭感觉 |
| **逐条改法** | 这个套话换成什么、哪句该删、改成什么更自然 |
| **逻辑漏洞** | 自相矛盾 / 答非所问 / 语义跳跃（需模型判断）|
| **申诉材料** | 被平台判为 AI 时可直接引用的论据 |

## 两种用法

### 用法一：网页版（免安装）

👉 **https://xieshougulishi.github.io/webnovel-ai-detector/**

打开后把正文粘进去即可。分析在浏览器里通过 WebAssembly 运行，不需要装任何东西。

**网页版只做量化分析**（风险分、证据定位、改法），不含逻辑漏洞判断与申诉材料。

### 用法二：装成 Agent Skill（功能完整）

仓库里的 [`skill/`](skill/) 目录就是完整的技能本体。

把整个 `skill/` 文件夹复制到你的 skills 目录：

```bash
# DSH
cp -r skill ~/.dsh/skills/webnovel-ai-detector

# Claude Code / 其他支持 Agent Skills 的客户端
cp -r skill <你的 skills 目录>/webnovel-ai-detector
```

然后在对话里发一段网文正文并说"检测一下"，agent 就会调用它。

**完整版比网页版多**：逻辑漏洞判断（由模型做）、已有作品识别、申诉材料生成。

#### 也可以直接用命令行跑

```bash
python skill/scripts/deliver.py --file 我的稿子.txt --title "第12章"
```

输出一个 `file:///...` 链接，浏览器打开就是完整报告。

只需要 Python 3.9+，**没有任何第三方依赖**。

## 它怎么算的

全部公式公开，报告页里有「方法学透明」区块可查。

```
单条规则得分 = 严重度(1-5) × 可信度(0-1) × 档位系数 × [超额分 + 极端加成] × (1 - e^(-命中次数/1.5))
               档位系数 = A级 2.0 | B级 1.0 | C级 0.4
               超额分   = min(超额倍数 - 1, 3)
               极端加成 = min(0.8 × log2(超额倍数 / 4), 1.5)

分类得分     = 100 × (1 - e^(-Σ规则得分 / 分类归一常数))
证据多样性   = 1 + 0.20 × min(有实质贡献(≥1.5分)的维度数 - 2, 3)
总风险       = 100 × (1 - e^(-证据总分 × 多样性 / 22)) - 0.30 × 人味证据强度
档位         = <18 极低 | <36 偏低 | <55 中等 | <72 偏高 | ≥72 极高
```

几个刻意的设计取舍：

- **只算超过人类基线的部分**——一个「仿佛」不是罪证，密度是基线的 19 倍才是
- **按实测区分度分 A/B/C 三档**——会误报的启发式（句长均匀度）不该和已证实的强信号（套话密度）同权
- **题材自适应只放宽、绝不收紧**——系统流、仙侠、古言本来就用词偏文
- **证据多样性加成**——8 条证据横跨 5 个维度，比 3 条挤在一处可信得多

## ⚠️ 已知局限（**请务必读**）

这些不是免责声明，是实测记录，全部写在 [`skill/references/calibration.md`](skill/references/calibration.md) 里。

**它是「AI 用词特征」检测器，不是通用 AI 鉴定器。**

| 类型 | 结果 |
|---|---|
| **词穷型 AI**（套话密集、句式模板化、逐字重复） | ✅ 抓得住（实测 79–98 分）|
| **啰嗦型 AI**（动作链堆叠、状语泛滥、连接词填空） | ❌ **漏检**（实测 31–32 分）|
| **语义崩坏型 AI**（早期弱模型，内容荒谬但不堆套话） | ❌ **漏检**（33 分）|
| **文学型 AI**（写法本身就好的） | ❌ **漏检**（9.7 分）|

**7 份实测样本里判对 3 份。**

**所以：拿到低分，理解为「没有抓到 AI 用词特征」，而不是「证明是纯人写」。**

报告里五档中的每一档都写了这句免责。

## 目录结构

```
.
├── index.html          网页版界面
├── py/                 网页版引擎（浏览器里跑）
├── skill/              ★ Agent Skill 本体
│   ├── SKILL.md            技能定义与完整流程
│   ├── meta.yaml           展示元数据
│   ├── data/lexicon_ai.json  词表与基线（可改）
│   ├── scripts/            引擎源码（11 个模块）
│   ├── references/         校准记录、规则目录、申诉指南
│   └── examples/           示例报告
└── .nojekyll           让 GitHub Pages 跳过 Jekyll 处理
```

`py/` 和 `skill/scripts/` 是**同一套引擎的两份打包**——前者供浏览器，后者供命令行与 agent。
