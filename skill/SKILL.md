# 网文 AI 痕迹检测（可解释版）

## 0. 这个技能解决什么问题

「朱雀」一类黑箱检测器让作者愤怒的原因不是分数低，而是**它不解释**：
不说哪一句触发的、不说判据是什么、不给申诉通道。

本技能的承诺正好相反：**每一条判定都给出位置、观测值、人类基线、成因机制和改法**，
并且把计分公式完整印在报告里，作者可以自己复算。代价是：我们**不声称"证明"**——
只给概率性的风险区间。

**一句话定位**：不是"AI 鉴定器"，是**给作者看的体检报告 + 申诉材料生成器**。

## 2. 标准流程

### 第 0 步：确认输入

| 情况 | 处理 |
|---|---|
| 用户粘贴了正文 | 存成临时 `.txt`（UTF-8）再跑 |
| 给了 `.txt` / `.md` | 直接跑 |
| 给了 `.docx` | 直接跑，`analyze.py` 内置解压兜底（不依赖 python-docx） |
| 给了多章合并的大文件 | 直接跑，但报告里要说明"整体结论 ≠ 每章结论" |
| 只有几百字 | **照跑，但必须转述报告里的"样本过短"警告**，不能当结论用 |

**绝对不要**把小于 300 字的样本当成 AI 判定依据。任何检测器在这个长度上都是猜。

### 第 0.5 步：已有作品识别（**必做，且必须在跑检测前完成**）用户发来的文本**可能根本不是他写的**——可能是名著、教材篇目、别人写的网文。
这种情况下面那个 AI 风险分会给出「极低」，而**低分恰恰是最大的误导**：
名篇大多写于 AI 出现之前，低分只说明它是人写的，不能说明它是作者的。

所以每次检测前，**你自己（模型）先判断一遍这段文字是不是已有作品**，再跑报告。

#### 判断方法

不要用关键词猜，也不要指望某个库——**用你的知识判断**：

1. **读完文本**，注意开篇句式、独特措辞、专有名词组合；
2. 自问：这段我是不是见过？出自哪一篇？
3. 有把握 → 填 `matched`；疑似但拿不准 → 填 `partial` + `confidence: medium`；
   完全没印象 → 填 `none` + `confidence: medium`（**不要填 high**，模型有知识截止和盲区）；
4. 能引出一句最能确认出处的原文 → 填 `distinguishing_line`；
5. 判断置信度不是 high 时，**必须**填 `verify_note`（告诉用户怎么核实）。

#### 判断结果的数据契约

```json
{
  "match": "matched | partial | none",
  "confidence": "high | medium | low",
  "work": {"title": "某篇教材必背篇目", "author": "作者", "era": "年份", "type": "modern_essay"},
  "coverage": 1.0,
  "evidence": ["开篇与该篇原文一致", "其中「XXXX」为原文语句"],
  "distinguishing_line": "最能确认出处的那一句原文",
  "reproduction_note": "已进入公有领域，但仍属他人作品；以自己名义发布属抄袭。",
  "verify_note": ""
}
```

- `coverage`：该作品占送检文本的比例。**整体照搬填 1.0**，节选按实际比例估，拿不准填 `null`。
- `match` 必填、`confidence` 必填、`evidence` 必填（schema 校验会拒绝缺字段，避免静默漏报）。

#### 传给报告

```powershell
& $py "<技能目录>\scripts\deliver.py" --file "稿件.txt" --existing '<上面的 JSON>'
```

或把 JSON 存成文件：`--existing existing.json`。

**判断结果是渲染层的一等公民，但只在检测到时上页面**：

| 判断结果 | 页面表现 | 回复正文 |
|---|---|---|
| `matched`（命中） | **页面最顶部**红/黄色横幅（作品名、作者、年代、置信度、占全文比例、"下面的风险分没有意义"），并多一个「已有作品识别 · 详情」区块 | 必须在回复里**第一句**就说这件事，比分数重要 |
| `partial`（疑似/节选/混排） | 黄色横幅 + 详情区块，措辞按「疑似」 | 同上，用"疑似"语气 |
| `none`（未识别） | **页面上完全不出现**（对作者没有行动价值，不占第一屏） | **必须用一句话如实交代**：「已检查过出处，未识别为已有作品——但这不等于原创」。见下方"为什么要交代" |
| 未做判断（没传 `--existing`） | **页面上完全不出现** | **必须如实说**："本次未做已有作品识别，只评估了 AI 痕迹" |

**为什么"未识别"不在页面上显示、却必须在回复里说**：
页面是给作者看的结论，没有信号的提示只会稀释真正重要的内容（用户明确要求过这一点）；
但"没查"和"查了没查到"对作者的心理预期是不同的——前者可能被误读成"没查也行"。
所以页面保持干净，**这件事由你在对话里用一句话交代清楚**。

#### 常犯的两个错

| 错误 | 后果 |
|---|---|
| 判断为 `none` 却填 `confidence: high` | 过度自信。模型知识有截止日期，冷门/新作/改写都可能识别不出。schema 校验会给警告，请改成 medium。 |
| 明明认出来了，但 `evidence` 留空 / 只写"风格像" | 用户无法复核，横幅变成一句没根据的指控。必须写具体依据（哪句一致、哪个句式）。 |

**如果你认出来了却没传判断结果**，页面不会报警（因为按设计未检测到就不显示横幅），
但你在回复里也**没提**——这对用户是**严重的失职**：他可能拿着一篇教材课文去投稿。
所以：**判断这一步不能省，判断完必须在回复里给一句话结论**。

### 第 0.6 步：逻辑漏洞识别（**必做，权重最高**）

**逻辑漏洞是 AI 最硬的破绽**：文风可以模仿，逻辑崩了就是崩了。
一个作者可能不小心写出 AI 腔，但不会在一千字里自我矛盾四五次。
所以这一步也由**你（模型）**判断，把结果作为高权重证据传给报告。

#### 为什么不能靠统计规则

我实测过一条"答非所问"的字符重叠指标：取问答对，算双方的实字重合度。
在一份早期 AI 文本上判出 5 处「答非所问」，**逐一核对后只有 1 处是真的**——
其余 4 处是「答对了，但换了词」：

```
问：那座森林里住着什么人？   答：我不清楚，老板从来没告诉过我。
```

答句当然不含问句的字符，但它是一个**正确的答案**。
**逻辑漏洞是语义关系，任何字面统计的代理指标都会重蹈覆辙。**
所以：统计规则管文体，你管逻辑。

#### 判断方法

通读全文，专门找这七类：

| 类型 | 判据 | 例子 |
|---|---|---|
| `contradiction` 自相矛盾 | 两处信息互斥 | 前文说某人被炸死，后文他活着出场 |
| `non_answer` 答非所问 | 问 A 答 B，且 B 没回答问题 | 问"头颅在哪"，答一段森林风景 |
| `jump` 语义跳跃 | 上句下句无逻辑连接 | 从"他是个傻瓜"跳到"他吃龙肉喝龙血" |
| `causality` 因果倒置 | 结果先于原因，或因果不成立 | — |
| `reference` 指代崩坏 | 代词找不到先行词，或指错人 | — |
| `world` 设定自相冲突 | 同一设定前后说法不同 | 前文说序列只有 1–999，后文出现序列 0 |
| `nonsense` 内容荒谬 | 事实层面不成立 | — |

**每条必须给 `quote`（原文片段）和 `why`（为什么矛盾，要具体到两个冲突点）。**
只写"逻辑有问题"不算——用户无法复核。

#### 数据契约

```json
{
  "holes": [
    {"quote": "原文片段（10-40字，用于定位）",
     "type": "contradiction",
     "severity": 5,
     "why": "为什么是漏洞（要具体到两个互相冲突的点）"}
  ],
  "summary": "整体判断（一句话）",
  "note": "（可选）判断的不确定性"
}
```

`severity` 1–5：3 = 明显但不致命；5 = 直接矛盾、读者会出戏。
**权重：每条 = severity × 1.2 分（severity 5 → 6 分），高于所有文体类规则。**

#### 传给报告

```powershell
& $py "<技能目录>\scripts\deliver.py" --file "稿子.txt" --coherence '<上面的 JSON>'
```

命中时报告会在**雷达图之前**插入红色「逻辑漏洞」面板，逐条列出类型、严重度、原因和原文。

#### 三条纪律

| 纪律 | 原因 |
|---|---|
| **不要把"文笔差"当逻辑漏洞** | 「我不喜欢这个写法」不是矛盾。必须是**两处信息互斥**。平均严重度 ≥4.5 且 ≥4 条时，schema 校验会警告。 |
| **答对了但换了词 ≠ 答非所问** | 我自己踩过的坑。判断时问：这个回答**实质上**有没有回答问题？ |
| **没找到就说没找到** | `holes: []` + summary 写"通读未见明显逻辑矛盾"。不要为了凑分硬挑。 |

**这一步的价值不只在加分**——它把"我看不出哪里不对，但就是不自然"
变成了**"第三段说老板死了，第五段他又活着出场"** 这种作者能自己去核对的话。

### 第 1 步：跑检测 → 拿到链接

**默认走 `deliver.py`，它会顺手把可点击的 HTML 链接准备好。**

```powershell
# 用宿主环境自带的 Python 3.9+ 即可（无第三方依赖）。
# 若你的 agent 运行时自带解释器（如 DSH 的 dsh-primary-runtime），指向它更稳；
# 否则直接用系统里的 python / python3。
$py = "python"

# 用户粘贴了正文
& $py "<技能目录>\scripts\deliver.py" --text "正文全文……" --title "第12章" --no-md

# 用户给了文件
& $py "<技能目录>\scripts\deliver.py" --file "我的稿子.txt" --no-md
```

`deliver.py` 做四件事：

1. 跑分析，产出 html / md / json；
2. 把 HTML **复制到固定交付路径** `<工作区>\检测报告\最新检测报告.html`；
3. 带时间戳的历史副本存进 `<工作区>\检测报告\history\`；
4. 最后一行输出 `DELIVER {json}`，从中取 `url` 字段。

**`url` 就是给用户的可点击链接**，形如：

```
file:///E:/<工作区>/检测报告/最新检测报告.html
```

**为什么用固定路径**：链接必须稳定。用户收藏一次，之后每次检测都是同一个链接，
刷新就是新结果；而不是每次都生成一个新文件名让他去文件夹里找。

### 第 1b 步：必须把链接写进回复（**硬要求**）

跑完检测后，回复里**必须包含这个 `file://` 链接**，写成可点击的 Markdown 链接：

```markdown
📄 [打开可视化检测报告](<file:///E:/<工作区>/检测报告/最新检测报告.html>)
```

**同时调用 `present`** 把 `最新检测报告.html` 作为文件卡片附上——
两条件都给，哪个能打开用哪个（Web GUI 里卡片可预览，链接可收藏复用）。

**不要**只报一句"报告已生成在 xxx 目录"——用户要的是能点开看的东西。
**也不要**只给相对路径或纯文件名，对话框里点不开。

### 第 1c 步：备选路径

| 情况 | 处理 |
|---|---|
| 工作区不可写 | 退回 `analyze.py`，把报告写到可写目录，用 `present` 交付 |
| 用户只要 TUI/飞书文本 | `deliver.py` 去掉 `--no-md`，Markdown 全文会打到 stdout，抄进回复正文 |
| 需要细粒度控制（批量、只出 json） | 用 `analyze.py`，参数见下表 |

`analyze.py` 常用参数：

| 参数 | 用途 |
|---|---|
| `--format md` | 只要文本报告（飞书/TUI 场景） |
| `--stdout` | 把 Markdown 打到标准输出 |
| `--out DIR` | 指定输出目录 |
| `--lexicon FILE` | 用作者自己的词表（自定义"我这本的高频词"） |

### 第 2 步：向用户解释结论（**这一步不能省，也不能只丢链接**）

按下面顺序讲，不要只说分数：

1. **档位 + 风险区间**，并明确说这是**区间**不是定值。
2. **最主要的两三条证据**，每条都要引用原文片段，让作者能立刻对上是哪句话。
3. **人味对冲结果**：报告里有哪些支持"这是人写的"的证据（口语、脏话、方言、
   语气词、写作噪声、半角标点）。这一节是作者最需要的东西——它既是信心来源，
   也是申诉材料。
4. **改法**：按性价比排序的前三条。明确区分"换词能解决"和"必须成段重写"。
5. **不确定性与失效场景**：如实转述。**不要为了讨好作者而隐瞒"可能低估"或"可能高估"。**

顺序建议：**先讲结论，再给链接**（让用户先看懂，再点开看细节）。

### 第 3 步：交付清单

- ✅ 回复正文含 `file://` 可点击链接（第 1b 步）
- ✅ `present` 附上 HTML 文件卡片
- ✅ 结论摘要与关键证据写成 `canvas_write_node`（kind=text），
  多章筛查建议写 table 节点，这样作者回到画布还能看到
- TUI / 飞书：Markdown 内容直接写进回复正文（飞书回复本身即可读），
  文件靠插件的自动送达机制发（**不要手动调 `send_file`**）

### 第 4 步：改稿后复检

作者改完再跑一次（同一个固定路径，链接不变），**必须对比两次的风险分与档位**，
并指出哪条证据被消掉了。不要只说"好了"——要说"套话密度从 21.5 降到 3.1，
对应少了 13 分"。历史报告在 `检测报告\history\` 里，可用于对比。

## 3. 关键规则（必须遵守）

### 3.1 措辞红线

| 不要用 | 要用 |
|---|---|
| 「AI 生成率 87%」 | 「AI 痕迹风险分 63，档位偏高」 |
| 「确认为 AI 生成」 | 「检出系统性 AI 痕迹」 |
| 「鉴定」「证明」 | 「概率性推断」「风险区间」 |
| 「你这就是 AI 写的」 | 「这些位置与 AI 的典型特征一致」 |

任何情况下都不能把报告结论表述成确定判定。这是这个技能存在的**前提**——
黑箱工具的可信度问题正是我们要解决的，如果我们自己也开始下确定结论，
就等于变成了另一个朱雀。

### 3.1b 页面必带声明（**已内置，别删**）

每份报告页面**最顶部**有一个固定声明块（HTML 与 Markdown 版都有），内容为：

> 页面内容由 AI 生成，只做 **AI 含量**的判断，并提供修改意见。
> **不保证结果一定准确**：给的是概率性风险区间，不是鉴定结论。
> **不评判作品好坏**：风险分低只说明「不像机器写的」，不代表写得好；风险分高也不代表作品差。
> **是否相信页面内容，请用户自行判断。**

这条声明在 `render_html.py` 的 `_disclaimer()` 与 `render_md.py` 的 `DISCLAIMER_ITEMS_MD` 里，
**不要为了页面简洁而删掉或折叠**。尤其「不评判好坏」这一句——它挡掉作者
把风险分当成作品质量评分来用的误读。

回复正文里转述结论时，也**不要**用「你写得好/差」这类判断。

### 3.2 不做代写

**拒绝整章改写请求。** 可以说清改法、给 1–2 句示范（并标注为示范），
但不能产出可直接提交的正文。理由（要向用户讲明白）：

- 起点等平台对 AI 代笔有明确处置并每月公示，帮作者洗稿等于把他推向封号；
- 洗稿的本质是**用 AI 掩盖 AI**，改出来的文本会更不像人写的（这有实测支持：
  人工改写会稀释典型痕迹，但不会把 AI 文本变成人写文本）；
- 本工具的价值在"让作者知道自己的毛病在哪"，而不是"绕过检测"。

用户坚持要"帮我把 AI 味降下去"时：给**改法清单 + 示范句**，
并说明为什么整章代改对他不利。

### 3.3 样本长度硬约束

| 字数 | 必须传达给用户的话 |
|---|---|
| < 300 | 拒绝给结论。告知"任何检测器在此长度都是猜"。 |
| 300–1000 | 给结论但强调区间已放宽，标注低置信。 |
| 1000–2000 | 正常给结论，但要提"建议单章 2000 字以上复检"。 |
| ≥ 2000 | 正常给结论，可提"逐章筛查"。 |

**平台若用几百字判定作者，本身就是方法论缺陷**——这一点要向用户点明，
它是有效的申诉论据，已写在报告的申诉章节里。

### 3.4 误报比漏报更致命

工具被作者抛弃的头号原因不是漏报，是**把真人写的判成 AI**。
因此：

- 新增规则前**必须先跑 `selftest.py`**，确认人写语料仍然落在中低档；
- 任何"启发式"规则（依据理论而非实测语料）都要在报告里标明，并压低权重；
- 题材自适应**只放宽基线，绝不收紧**（代码里写死，见 `rules.py` 的 `GENRE_ADJUST`）；
- 人味证据只能**抵扣**风险分，不能变成加分项。

## 4. 报告怎么读（转述给用户时用）

| 区块 | 含义 |
|---|---|
| 风险区间仪表盘 | 中心数字是风险分；外侧灰色弧是**不确定区间**，同一份文本换检测器大概率落在带内 |

## 5. 分数怎么算出来的（简版，要能对用户讲清楚）

```
单条规则得分 = 严重度(1-5) × 可信度(0-1) × 档位系数 × [超额分 + 极端加成] × (1 - e^(-命中次数/1.5))
               档位系数 = A级 2.0 | B级 1.0 | C级 0.4
分类得分     = 100 × (1 - e^(-Σ规则得分 / 分类归一常数))
证据多样性   = 1 + 0.20 × min(有实质贡献(≥1.5分)的维度数 - 2, 3)   # 维度≤2 不加成
总风险       = 100 × (1 - e^(-证据总分 × 多样性 / 22)) - 0.30 × 人味证据强度
区间         = 风险 ± (证据分散 5-14 + 样本长度 0-12 + 短样本放宽 0-15)
档位         = <18 极低 | <36 偏低 | <55 中等 | <72 偏高 | ≥72 极高
```

设计要点（用户问起时用得上）：

- **只有超过人类基线的部分计分**，且超额倍数封顶 3 倍——防止单一极端值主导结论；
- **命中次数用饱和曲线**——分散的多样痕迹比同一条痕迹反复出现更说明问题；
- **档位系数（A/B/C）**：按**实测区分度**分档，避免"权重平均化"。
  实测能区分人写与 AI 的（套话、逐字重复、总结词、对偶/比喻模板）是 A 级 ×2.0；
  实测会误报的启发式（句长均匀、排版、标点熵）是 C 级 ×0.4。
  权重跨度 **24 倍**——一条 A 级强信号不会被一堆弱启发式摊平。
  **分档依据写在 `rules.py` 的 `TIER_MAP` 注释里，每条都可追溯到 calibration.md 的实测记录。**
- **最低命中数**：词表类规则除了密度，还要求绝对命中次数够（短文本 ≥4 次）——
  否则 531 字里 3 个「仿佛」会被密度放大成"远超基线"；
- **证据多样性加成**：证据横跨 4 个独立维度比全挤在 1 个维度可信得多；
- **极端加成**：超额 >4 倍时给对数加成（封顶 +1.5），因为「19 倍」和「4 倍」不该同分；
- **人味证据最多抵扣 30 分**（乘数固定），因为存在"人写得很齐整"和
  "AI 被刻意加了口语"两种可能，抵扣不该决定档位。

## 6. 常见问题的应答口径

**Q：准不准？**
直接说：这是**概率性**推断，不是鉴定。本工具的价值在于可解释与可复核，
不在于给出一个权威分数。任何声称能确定判定的 AI 检测器都在骗人。
然后给出报告里的区间宽度——**区间越宽，说明结论越不确定，这是诚实。**

**Q：为什么朱雀判我 87%，你只判 40%？**
说明两者口径不同：朱雀类工具基于困惑度/突发性（需要服务端模型），
本工具基于可本地观测的文体统计特征。两者都只是概率估计。
**关键区别是：本工具的每一条判据你都能自己复核，朱雀的不能。**
如果本工具判低而朱雀判高，报告里的"体检表"和"误判对冲"正好是可以拿去申诉的材料。

**Q：我想让分数再降一点。**
可以，但要区分两种情况：
① 确实有 AI 味（套话密度高、段段升华）→ 按处方改，这是真的在改文；
② 分数已经很低了还想刷分 → 明确劝住，刷分会把文本改得更不像人写的，
而且平台检测器会更新。

**Q：能不能帮我整章改写？**
见 §3.2，拒绝，并说明理由。

**Q：我想加固态词表/自己的基线。**
读 `references/calibration.md`。

## 7. 边界（明确不做的事）

- ❌ 代写、整章改写、洗稿（§3.2）
- ❌ 英文文本（词表与基线都是中文网文）
- ❌ 学术论文 / 公文 / 新闻稿（文体基线完全不同，套用会误判）
- ❌ 法律意义上的鉴定结论
- ❌ 判定"作者是否用了 AI"（本工具只能描述文本特征，不能认定创作主体）
- ❌ 预测某个具体平台会不会判定（各平台判据保密且会变；本工具只说风险区间）
