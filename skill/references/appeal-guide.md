# 被平台判定为 AI 之后的应对指南

> 这份文档给**作者**用。当番茄/起点等平台判定你的作品使用了 AI，
> 而你想搞清楚原因、准备申诉材料时，按本文档走。

---

## 0. 先分清三种情况

平台判定你的作品是 AI，可能是三种完全不同的情况。**处理方式完全不同**，
先判断自己属于哪一种：

| 情况 | 特征 | 应对重点 |
|---|---|---|
| **A. 纯误判**（完全人手写） | 本工具跑出来风险 < 36；有自己的写作过程记录 | 走申诉，材料准备见 §2 |
| **B. 有 AI 参与，但不是代笔**（如用 AI 润色、扩写大纲、查错字） | 本工具跑出中间档 36–60；能说清哪部分用了 AI | 坦白 + 补救，重点在"是否达到平台 AI 代笔的认定标准" |
| **C. 确为 AI 生成** | 本工具跑出 > 60，且自己心里清楚 | 不要申诉。申诉会被平台复核后加罚。直接改写或重开新书 |

**先跑检测，再决定要不要申诉。** 本工具的报告正是为这个判断服务的。

## 1. 为什么平台会误判

平台用的检测器（含朱雀类）和我们面临同样的困难，但它们的错误更难被纠正，因为：

1. **它们不公开判据**，你无法知道哪句话触发的，也就无法针对性反驳；
2. **它们通常在短样本上判定**。如果你的作品被抽样检测了 500 字，
   那么**任何检测器在这个长度上都不具备可靠性**——这是方法论缺陷，不是你的问题；
3. **它们把"文体特征"当成"创作过程证据"**。一句"仿佛带着一丝凉意"
   是写作习惯，不是 AI 签名。人也会这么写；
4. **类型文的天然特征被当成 AI 特征**。系统流的属性面板、签到流的重复句式、
   战神文的打脸套路——这些是人写的类型文特征，但统计上很像 AI。

这四点里，**第 2 点是最有力的申诉论据**（见 §2.3）。

## 2. 申诉材料怎么准备

本工具的报告已经内置了「如果被平台判定，可以用这些论据申诉」章节。
下面说明怎么用，以及报告之外你还应该准备什么。

### 2.1 直接引用报告里的客观数据

报告「体检表」一节里的所有指标都是**客观测量值**，不依赖本工具的判定逻辑。
它们可以独立使用。**优先引用这几项**：

| 指标 | 为什么有用 |
|---|---|
| **半角标点混入比例** | 中文输入法产生不了半角标点。这是最难被生成模型复现的痕迹。如果你的文本里有，直接截图。 |
| **「的/地」不规范写法次数** | 真人写作噪声。AI 输出几乎总是语法规范。 |
| **人味证据清单** | 口语、脏话、方言、语气词的具体词与次数。逐条列出。 |
| **句长四分位距 / 短句占比** | 如果你的文本句子长短落差大，这是"人在写作时会突然甩短句"的证据。 |
| **风险区间宽度** | 本工具自己承认的不确定度。可以说："连这个工具都认为存在 XX 分的不确定度。" |

### 2.2 引用报告里的方法论主张

报告申诉章节的最后一条是最重要的，**建议原文引用**：

> 现有 AI 检测器普遍基于困惑度与突发性，其输出是概率性的，
> 不构成对创作主体的认定。若平台以单一分数作为处置依据，
> 可要求其公开判定阈值、检测文本范围与复核机制。

配套说法：**"请平台说明判定所依据的具体文本范围、检测模型版本与阈值。"**
多数平台的客服话术里没有这些信息，这本身就是可以追问的点。

### 2.3 追问检测样本长度（最有力的论据）

如果平台告知了检测范围，或者你怀疑是抽样检测，务必指出：

> 若本次判定基于 X 字样本，则该样本长度低于任何检测器具备统计可靠性的最小长度。
> 本工具在 <300 字时直接拒绝对 AI 含量下结论，<1000 字时强制放宽区间并标注低置信。
> 请平台说明其检测器在 X 字样本上的准确率与误报率。

**这个追问很难被正面回答**，因为公开数据里没有检测器愿意公布短样本误报率。

### 2.4 报告之外必须准备的材料（本工具无法代劳）

这些是**创作过程证据**，比任何文体分析都有说服力。**平时就要留**：

- **写作软件的时间线记录**：章节的编辑历史、字数增长曲线。
  真实的写作过程是**断续的、有长时间停顿的、有大量删改的**；
  AI 生成是一次性大段产出。这是最硬的证据。
- **草稿与修改痕迹**：手写稿照片、多个版本的迭代文件、
  丢掉的废稿（废稿里往往有更烂的句子——AI 不会产出"越来越好的废稿"）。
- **与读者的互动记录**：连载期间的读者评论、回复，时间戳能证明持续创作。
- **素材与笔记**：人物设定、大纲、考据资料、甚至购物记录里买过的参考书。
- **大纲与实际正文的对应关系**：能说清"这一段是从哪个大纲节点发展出来的"。

**建议**：从今天起用带版本历史的写作工具（Git、或以日期命名的多版本文件），
并在每章完成后留一个截图。**这比事后任何申诉都有效。**

## 3. 申诉的写法

### 3.1 结构

```
1. 事实陈述：作品名、作者号、被判定时间、平台给出的判定结论
2. 反驳材料：
   2.1 创作过程证据（时间线截图、草稿、修改记录）
   2.2 文体客观数据（引用报告的体检表与人味证据）
   2.3 方法论质疑（检测样本长度、判据不透明、无可复核性）
3. 请求：撤销判定 / 人工复核 / 说明判定依据
```

### 3.2 措辞注意

**该说**：
- "报告显示……"（引用客观数据）
- "该工具自认存在 XX 分不确定度"（引用工具自身的局限）
- "请平台说明判定依据"（把举证责任交回去）

**不该说**：
- "你们的检测器很蠢"（情绪化，客服会直接结束对话）
- "另一个工具说我不是 AI"（工具对工具的对抗没有意义，
  除非你能拿出**客观测量值**）
- "我要投诉/起诉"（作为第一句会关闭沟通渠道；留到无果之后）

### 3.3 如果申诉失败

**不要为了"过检测"去洗稿。** 理由：

1. 洗稿是用 AI 掩盖 AI，改出来的文本会更不像人写的；
2. 平台的检测模型会更新，下一次可能还会被判；
3. 部分平台对"规避检测"本身有单独处罚，比 AI 代笔更重。

**更好的选择**：把被判定的章节按本工具的处方**真正重写**（不是换词，是改结构），
并保留重写前的版本作为"我在改"的证据。或者放弃这本，开新书时从第一章就留创作痕迹。

## 4. 预防：下次怎么不被判

| 做法 | 原理 |
|---|---|
| 有意识地打破句式均匀：情绪点用极短句，交代场景用长复句 | 提高句长变异系数 |
| 少用「仿佛/一丝/缓缓/微微/若有所思」 | 压低套话密度（**最强信号**） |
| 别让每段都收尾升华，让段落停在动作或对白上 | 降低段末总结率 |
| 多用具体到生理层面的身体细节，少用"瞳孔一缩/心中一紧" | 降低通用身体反应密度 |
| 写气味、触感、味道 | 补足五感分布 |
| 对白写碎一点：抢话、重复、说半截、答非所问 | 提高对白真实感 |
| **不要刻意写错别字来"装人"** | 噪声可以被检测为刻意添加，且损害作品质量 |
| **坚持用自己的话写** | 这是唯一根本的解决办法 |

## 5. 关于"AI 辅助"的边界

很多作者问：**用 AI 帮我查错字/整理大纲/想标题，算不算 AI 代笔？**

本工具不能替平台回答这个问题，但可以说清楚判断逻辑：

| 用途 | 普遍认知 |
|---|---|
| 查错字、标点、排版 | 工具性使用，与拼写检查同类 |
| 整理大纲、生成人物名、想标题选项 | 辅助构思，最终由人判断取舍 |
| 润色句子（让 AI 改写你写好的句子） | **灰区**。改写程度越深越接近代笔 |
| 由 AI 生成段落内容，人再修改 | **接近代笔**。本工具对这类文本会给中间档 |
| 由 AI 生成整章，人只改错字 | **代笔** |

**本工具的态度**：不给法律/合规结论，只说明——如果你用了灰区及以上的做法，
那么平台判定你的时候，本工具的报告也会显示中间档或偏高档，
**这时候申诉成功率很低，如实处理比硬撑更好。**
