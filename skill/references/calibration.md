# 校准与准确率

> 这份文档回答三个问题：**这工具准不准？自测结果如何？怎么提升准确率？**

---

## 1. 自测语料与结果

自测语料在 `<技能目录>/../../corpus/`（开发期目录），六份样本，分四类：

| 类别 | 文件 | 期望落区 | 检查的失败模式 |
|---|---|---|---|
| 人写 | `human_system_cultivation_01.txt`（系统流，含口语、脏话、"哐"字、错别字） | 极低/偏低 | **误报** |
| 人写 | `human_urban_daily_01.txt`（市井日常，大量口语与语气词） | 极低/偏低 | **误报** |
| 边界（人写文学向） | `edge_human_wuxia_literary_01.txt`（武侠，中性克制，少对白） | 极低，且必须不误报 | **误报** |
| AI | `ai_xianxia_romance_02.txt`（高浓度 AI 味仙侠言情） | 偏高/极高 | **漏报** |
| AI | `ai_urban_revenge_01.txt`（都市逆袭，典型 LLM 输出） | 偏高/极高 | **漏报** |
| AI（碎片化） | `ambiguous_ai_system_01.txt`（系统流 + 大量短段对白，痕迹被稀释） | 中等，**不得声称极高** | **过度自信** |

### 语料外发现二：标点熵无区分度（v1.0.0 修正）

用一份用户提供的**完整章节**（1832 字，对白占比 36%）实测时发现：

- 初判风险 **17.55**，最大单项是 `PUNCT_ENTROPY`（2.57 分，"标点种类过少"）；
- 核查标点实际分布：逗号 133、句号 137、问号 16、冒号 4、破折号 12、引号 48，
  **种类 6 种**，破折号用了 6 处、问号 16 个——完全没有"标点单调"这回事；
- 对照 AI 样本：归一化熵 **0.17–0.18**；真人样本 **0.21–0.30**。**两者严重重叠**；
- 更关键的是：原阈值设成 0.60，而**没有任何样本能超过 0.60**——
  意味着这条规则会对**所有文本**无条件命中。这是个纯粹的 bug。

修正：
1. `PUNCT_ENTROPY` 阈值 0.60 → **0.14**，严重度 3 → 2，可信度 0.58 → 0.45，
   并明确标注为**弱规则、单独命中不构成嫌疑**；
2. `PUNCT_CONCENTRATION`（逗号+句号占比）阈值 0.90 → **0.88**，严重度 3 → 4，
   可信度 0.58 → 0.70 —— 实测**这才是标点类唯一有区分度的指标**
   （真人 77%–89%，AI 89%–94%）。

修正后同一章节风险 **17.55 → 9.05**，标点分类归零。

### 语料外发现三：两类"看起来像信号"的伪特征

同一份用户章节还暴露了两个**不该计入**的模式：

| 伪特征 | 为什么剔除 |
|---|---|
| **"中英数混排无空格"**（`F级`、`Lv.7`、`7562号`） | 曾被计入"写作噪声"。但系统流/异能流网文的世界观本身就长这样，是全篇内容特征；**AI 同样会产出"F级"**，两边都出现 → 无区分度。 |
| **泛化的「XX的+任意字」** | 会被用来匹配"的/地"不规范写法，但「脸上的笑容」是完全正确的"形容词+的+名词"结构，被误判成噪声。已收紧到「副词性修饰语 + 的 + 动词」白名单，并加"总计 ≥8 处才纳入统计"的门槛——零星几处不构成"写作噪声"这个统计现象。 |

**这两条共同的教训**：一个特征要进规则表，必须先证明它**能区分人写与 AI**。
仅仅"看起来像不像 AI"不够——`F级` 看起来不像人写的自然语言，但它恰恰是
真人写的系统流网文里最正常的东西。

### 语料外发现四：段首重复规则对"正常叙事"系统性误报（v1.0.0 修正）

用一份用户提供的**三章连续文本**（5408 字，494 段，对白占比 26%）实测，暴露出
`RHY_PARA_HEAD` 这条规则的**三层连续失效**——每一层修完都还有下一层：

| 层 | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 命中位置全是主角名 | 双人对白场景段落必然交替以角色名开头 | 加 `detect_names()` 自动排除专名 |
| 2 | 专名识别返回**空集** | 判据太宽（30 个候选），触发了我加的"识别出 >3 个就全部放弃"保险丝 → **一个名字都没排除**。那根保险丝本身就是错的设计：群像文本本来就该识别出多个名字 | 改成**按频次排序取前 N 个**，不再整体放弃；函数说明里记下了这个坑 |
| 3 | 修完仍命中「两人」「什么」「没有」「再往」「楼梯」「教室」 | 中文小说里**段落以短词起手是常态**，这些普通语素在任何真人小说里都会反复出现在段首。规则想抓的"机械化起手"信号被这些噪声盖过 | 把严重度 3→2、可信度 0.80→0.45、阈值放宽到 2.0/千字，**明确标为弱规则**，并在 docstring 里写清"真正的节奏信号应看句长变异系数与四分位距" |

期间还发现一个**前缀漏洞**：识别出「陆行舟」后，规则只排除全名，而它取的是段首**两字**，
于是继续打在「陆行」上。已在第三级补上前缀展开。

**最终效果**：同一文本风险 **34.04 → 17.13**，档位 偏低 → **极低**；
节奏分类 19.1 → 3.6；`RHY_PARA_HEAD` 从 7.20 分降到 1.26 分。
AI 样本的检出能力基本未受影响（`ai_urban_revenge_01` 63.2 → 62.3）。

**这一条最值得记的教训**：`RHY_PARA_HEAD` 前后修了四次、每次都以为修好了。
段落起手重复在中文小说里**根本不是一个有区分度的特征**——
它作为规则能留在表里，只是因为权重压到足够低之后它不再造成实际伤害，
而不是因为它真的有判别能力。**如果一个特征要改四次才能不误报，它大概不该待在那里。**

### 语料外发现五：说话人标注计数把普通词当成了标注（v1.0.0 修正）

用一份用户提供的**恐怖悬疑章节**（2297 字，对白占比 12.3%）实测时发现：

- 初判风险 **23.79**，最大单项是 `DLG_TAG_VARIETY`（5.22 分，"说话人标注单调"）；
- 查明细：`{'说': 4, '道': 11}`，种类占比 0.069 —— 看起来这个作者确实只用"说/道"；
- 但把命中位置打出来后真相是：**这 11 个「道」几乎全部来自「味道」「知道」「一道」，
  4 个「说」来自「与其说……不如说……」。这篇文本其实几乎没有说话人标注**
  （该文本其实几乎不用标注词，而是用动作承担，如"某人面无表情""某个声音响起"这类）。

根因：标注词是**全篇子串计数**。`道` 是单字，天然被「味道」「知道」「难道」「街道」
吃掉；`说` 被「与其说」「不如说」吃掉。种类占比因此被稀释到接近 0，
规则就以为"这位作者只会用一两个标注词"。

修正：改为 `dialogue_tag_profile()`，**只统计紧贴引号出现的标注词**——
人类写对白的标注只有两种位置（标注在引号前 / 标注在引号后），
所以只看每段对白引号前后的一个小窗口，就能滤掉绝大多数假命中。
另外加了两个小保险：单字标注前若跟「知/味/一/难/街…」这类前置字则不计；
标注后若跟「的/了/着」则不计。

**修复效果**：同一文本标注数 **15 → 0**，风险 **23.79 → 6.86**，档位 偏低 → **极低**；
规则因"标注数不足 8 次"被正确跳过。

**正负例验证**（写进测试过程）：

| 输入 | 修复前 | 修复后 | 期望 |
|---|---|---|---|
| 8 种不同标注各一次 | 8 | **8** | ✓ 全认出 |
| 全是「味道/知道/难道/一道/与其说…不如说」 | 多个假命中 | **0** | ✓ 归零 |
| 2 个真标注 + 「味道」 | 3 | **2** | ✓ 「味道」里的道被忽略 |

**又一次同样的教训**：这是第四条因为"把正常叙事当信号"而误报的规则，
和 `RHY_PARA_HEAD` 是同一类错误——**中文里的单字、双字片段在普通词语里到处都是，
子串计数几乎必然误报**。统计任何词表特征之前，都必须先问一句：
"这个词会不会在别的常见词里出现？"

### 语料外发现六：7 条规则从来没生效过（死代码 bug，v1.1 修正）

用一份用户提供的**都市黑道章节**（1806 字）实测时，风险分给出 **0.00**——
七个分类全是 0、命中 0 条。这本身不算错（该文本确实干净），
但顺着"体检表里对白占比 8.6% 标红了、对应规则却没出现"这条线索查下去，
发现了一个**比误报严重得多的问题**：

**27 条规则里有 7 条从未执行过。**

| 原因 | 影响的规则 |
|---|---|
| `RuleContext.metric()` 只支持特征字典的虚线路径（`"sentence.cv_han"`），**不支持以 `_` 开头的模块内计算函数**。这些规则每次取指标都拿到 `None`，`evaluate()` 直接 `return None` | `DLG_RATIO_LOW`、`DLG_FLUENCY`、`EMO_SENSORY`、`STR_PARA_TAIL`、`STR_ONE_LINE` |
| 规则里写的函数名和实际定义的函数名不一致（`_clause_cv` vs `_clause_len_cv`、`_spp_cv` vs `_sent_per_para_cv`） | `RHY_CLAUSE_CV`、`RHY_SENT_PER_PARA` |

**为什么这类 bug 特别危险**：它不报错、不崩溃、不警告。
规则表看起来是满的（27 条），报告里也照常列出"未评分规则"，
但**有一整批特征从来没被检过**。用户看到的是"分数低"，看不到"有一半规则是死的"。

修正：
1. `metric()` 增加对 `_` 前缀的解析（`globals().get(path)` 取模块函数）；
2. 修正两处函数名不一致；
3. **新增一道结构性检查**（`selftest.py` 的"第三道：规则表完整性"）：
   逐条验证每个 `ThresholdRule` 的 metric 至少能在某个样本上取到值、
   每个 `PatternRule` 的抽取器能跑通、ID 唯一、分类合法。

**这道检查是真有牙的**——我故意把 `_dialogue_ratio` 改成 `_dialogue_ratio_typo`
验证它会报警，确实抓到了：

```
以下阈值规则取不到指标，永远不会触发（很可能是名字写错或解析不支持）：
    DLG_RATIO_LOW → metric='_dialogue_ratio_typo'
```

**修复后的连带影响**（说明这批规则原本缺失得多严重）：
AI 样本分数普遍上升（`ai_urban_revenge_01` 62.3 → **65.3**，
`ai_xianxia_romance_02` 73.1 → **75.2**），
人写样本基本不变（0–4.0）。**漏报率下降了，误报率没变**——这正是想要的方向。

**教训**：自测语料能验证"分数对不对"，但验不出"规则有没有在执行"。
前者靠样本，后者必须靠**结构性检查**。以后新增任何规则，都要先让完整性检查跑一遍。

### 语料外发现七：五感词表漏词，把写足的感官冤枉成"偏视觉"（v1.1 修正）

用一份用户提供的**末世科幻章节**（2072 字）实测时，风险 **15.77**，
最大单项是 `EMO_SENSORY`（3.65 分，"五感严重偏视觉，嗅味触觉缺失"）。

但这段明明写了：

| 原文 | 属于 |
|---|---|
| 「呛人的焦糊里」 | **嗅觉** |
| 「汗珠浸透了掌心」 | **触觉** |
| 「指甲嵌进肉里」「指尖泛白」 | **触觉/痛觉** |
| 「手止不住地发抖」 | **触觉** |

一查词表——`焦糊`、`呛人`、`汗珠`、`掌心`、`嵌进`、`泛白`、`发抖` **一个都没收录**。
五感检测当时算出来 嗅=0、触=0、味=0，于是判"偏视觉"。

**这是词表覆盖不足造成的误报**，不是规则逻辑错。

修正：把常见但被漏掉的感官词补齐——嗅觉加「焦糊/呛人/焦味/糊味/烟味/恶臭/馊/霉/冲鼻/铁锈味/消毒水」，
触觉加「发烫/发凉/泛白/汗珠/掌心/嵌进/疼痛/发抖/浸透/硌/寒意/攥紧/绷紧」等。

**修复效果**：嗅 0 → 0.0435、触 0 → 0.1957，三感合计 0.239 > 阈值 0.10，
规则不再触发；风险 **15.77 → 3.07**。

**这条规则的方向决定了修法很安全**：它只在"占比**偏低**"时触发，
所以**词表越全，误报越少**——补词只会让它更保守，不会制造新的误报。

顺带暴露一个**测试覆盖缺口**：`EMO_SENSORY` 要求样本 ≥2000 字，
而自测语料里最长的一份只有 821 字 —— 意味着**这条规则在自测里从来没被真正跑到过**。
它的第一个真实用例来自用户文本，第一个 bug 也是。已在下方"覆盖缺口"一节记录。

### 语料外发现八：一句一段的排版被当成"机械切段"（v1.1 修正）

用一份用户提供的**奇幻冒险章节**（5688 字，三章）实测，风险 **16.70**，
主项 `RHY_SENT_PER_PARA`（3.12 分，"每段句子数几乎一样"）。

查数据：**238 段 / 239 句 = 平均每段 1.00 句**，单句段占 99.6%。

这不是机械切段——**这是一句一段的排版，网文手机阅读的标准写法**。
短句、对白各自独立成段，让手机屏幕上每段都短、不挤。
"每段句数"的变异系数此时必然趋近 0，但这个 0 反映的是**排版习惯**，不是生成痕迹。

修正：给规则加前置条件——**平均每段 ≤1.1 句时跳过**，并如实写进"未评分规则"。
只有段落普遍含多句时，变异系数偏低才说明"每段都写成一样长的小单元"。

### 语料外发现九：`RHY_PARA_HEAD` 整条移除（v1.1）

同一份文本里，`RHY_PARA_HEAD` 又一次命中（例：「不过」起手，1.63 分）。

这是它**第四次**产生误报：

| 轮次 | 误报源 | 当时的修法 |
|---|---|---|
| 1 | 双人对白段落必然交替以角色名开头 | 加专名排除 |
| 2 | 专名识别返回空集（保险丝设计错误） | 改为按频次取前 N |
| 3 | 三字名只排除了全名，规则仍打在「陆行」上 | 补前缀展开 |
| 4 | 「两人/什么/没有/再往/不过」等普通词反复出现在段首 | —— 修不动了 |

它的检出贡献一直很小：即使在**高浓度 AI 样本**上也只占 0.1–0.4 分，
因为真正有区分度的词汇信号（套话密度）早早把它盖过去了。
**误报成本远大于检出收益，决定整条移除。**

移除后 AI 样本分数几乎不变（`ai_urban_revenge_01` 65.3 → 64.9，
`ai_xianxia_romance_02` 75.2 不变），人写样本照旧——证明它本来就在做无用功。

**这是第一次主动删规则而不是调参数。** 依据是 `calibration.md` 里早就写下的一句话：

> 如果一个特征要改四次才能不误报，它大概不该待在那里。

### 语料外发现十：ASCII 直引号的对白完全不可见（v1.1 修正）

用一份用户提供的**丹道仙侠章节**（1520 字）实测，风险 16.02，
其中「对白占比过低」命中 2.16 分，理由是"对白占比 0.0%"。

但那份稿子明明通篇都是对话。原因：**它用的是 ASCII 直引号 `"`，不是中文弯引号 `""`**——
全文 44 个 `"`，旧版对白识别只认中文引号，于是**整篇对白对引擎隐形**。

这不是罕见情况：作者用英文输入法、或从纯文本源复制粘贴，都会产生直引号。
中文输入法本身打不出 `"`，所以它同时也是**很强的人味证据**。

修正：
1. `iter_dialogue_spans()` 增加直引号支持——同一段里若有中文引号优先按中文解析，
   否则把 `"` **顺序两两配对**；
2. `punct_profile()` 增加 `straight_quotes` 统计，并计入半角占比
   （正文以汉字为主时，所有 `"` 都算混入，不管它前面是不是汉字——
   很多对白行是段落开头）。

**效果**：该文本对白占比 0% → 9.3%，风险 **16.02 → 9.73**（当时）；
连同下面这条分类修正后最终 **4.28**。

**顺带发现：我自己的语料也被污染了。** 核查发现 `ai_urban_revenge_01` 有 14 个 ASCII 直引号、
`ai_xianxia_romance_02` 有 22 个——**是我造语料时打进去的**，不是 AI 输出的特征。
真实 LLM 输出用的是中文弯引号。已把三份 AI 语料的直引号全部转成 `""`。
修正后 AI 样本对白占比从 0%（`ai_xianxia`）恢复到 11.8%，分数回到 73.1。

**这条的意义**：语料造假的方式比想象的多。我造"AI 样本"时用了我自己的打字习惯，
而这个习惯恰好和"人写"高度相关——**等于给 AI 样本掺了人味**。

### 语料外发现十一：人味证据被挂在风险分类下（v1.1 修正）

同一轮修完直引号后，`PUNCT_HALFWIDTH` 开始命中——按理这是好事（人味证据）。

但分数反而**涨了 16.5 分**。查下去发现：这条规则被挂在 `punct` 分类下，
而 `punct` 是**风险分类**（`risk=True`）。规则文案写着"反向项：命中说明更像人写的"，
代码却把它算进风险。

**这是方向反了的逻辑错误**：一条人味证据在给作者加罪。

修正：把 `PUNCT_HALFWIDTH` 从 `punct` 移到 `openness`（人味分类）。
现在它命中会**抵扣**风险分（本样本：人味强度 19，抵扣 5.8 分）。

**这类 bug 特别隐蔽**：规则表看起来正常、指标能取到值、分数也不报错——
只是方向反了。完整性检查（第三道）能抓"取不到指标"，但抓不到"分类挂错"。
所以又加了一条自检：**`openness` 分类下的规则 ID 必须以 `OPN_`/`PUNCT_HALFWIDTH` 开头
且该分类 `risk=False`**——见 `selftest.py` 的分类方向检查。

### ★ 语料外发现十二：一次确认漏检，以及本工具的能力上限（v1.1）

用户提供了一份 1520 字的**丹道仙侠章节**，并明确指出**作者自称由 AI 生成**。

本工具的判定：**9.73 分，「极低」，区间 0–31**。**这是一次彻底的漏检。**

这是目前所有测试里最重要的一条记录，因为它暴露的不是 bug，是**方法的边界**。

#### 这份 AI 文本长什么样

| 特征 | 实测值 | 人类基线 | 结论 |
|---|---|---|---|
| 文艺腔套话 | 1.97/千字 | ≤1.2 | 刚过线，**几乎没用** |
| 抽象情绪词 | **0.00** | ≤6.0 | 完美避开 |
| 通用身体反应 | **0.00** | ≤5.0 | 完美避开 |
| 书面连接词 | **0.00** | ≤9.0 | 完美避开 |
| 句长变异系数 | **0.821** | ≥0.45 | 起伏充分，反而更"人" |
| 段长变异系数 | 0.784 | ≥0.35 | 同上 |
| 短句占比（≤5字） | **24.5%** | ≥8% | 同上 |
| 五感分布（嗅+味+触） | 0.20 | ≥0.10 | 达标 |

**它把本工具最依赖的每一个信号都避开了。** 而且不是偶然避开——
它的写作方式（短句独立成段、大量具体细节、零抽象抒情、零套话）恰恰是
"高质量文学化写作"的特征，而本工具把这些当成了"人味"。

#### 试过但不成立的新思路

为了抓它，我试了两种**不依赖词表**的统计量：

| 思路 | 结果 |
|---|---|
| **gzip 压缩率**（AI 更可预测→压缩更好） | 长度受控后（固定 500/800 字）**无区分度**：确认 AI 0.9230，人写 0.9174–0.9382，AI 样本 0.8887–0.9246，全部重叠 |
| **固定长度用字丰富度 TTR** | 同样**无区分度**：确认 AI @500字 0.4740，人写 0.4480–0.5160，AI 样本 0.4660–0.5960 |

压缩率在**不同长度之间**看起来有信号（1520 字 0.8575 vs 538 字 0.9298），
但那是长度效应，不是作者归属。**凡是会随长度单调变化的统计量，都必须先固定长度再比较**，
否则会得到一个看起来很漂亮、实际上只是在测长度的假信号。

#### 同时修掉的一个真错误

这份文本有 44 个 **ASCII 直引号**，旧版把它们当作"半角标点＝人味证据"，
贡献了 19.4 分的人味强度、抵扣 5.8 分。

**这个判断从原理上就是错的**：

| 场景 | 引号形态 |
|---|---|
| 人写 + 聊天窗口复制 | ASCII `"` |
| **AI 写 + 聊天窗口复制** | **ASCII `"`** |
| 人写 + 输入法直出 | 弯引号 `""` |
| AI 写 + 直接导出 | 弯引号 `""` |

直引号说明的是**"这段文字经过了什么渠道"**，不是**"谁写的"**。
已把直引号从"半角人味证据"中移除（它仍参与对白解析——解析与证据是两件事）。
修正后该文本风险 4.28 → **9.73**，人味抵扣 5.8 → 0.4 分。

#### 结论：本工具的能力边界

**能抓**：风格平庸、依赖套话、情绪命名化、五感缺失的典型 LLM 输出（实测 40–75 分）。
**抓不住**：刻意避免套话、细节具体、节奏有设计的高质量 AI 输出（实测 9.73 分）。

这不是靠加规则能解决的——**任何基于"数特征"的方法，遇到刻意不产生这些特征的文本都会失效。**
真正的解法是算困惑度（需要本地模型）或依赖生成端水印，两者都超出本工具的条件。

#### 因此新增的一条报告声明

只要**风险 <18 且样本 ≥800 字**，报告会自动加入一条声明：
**「极低」不等于「排除 AI」**，并附上这次漏检的具体数据。

不加这条，用户会把"极低"当成"证明是纯人写"——**那比给错分数更危险**。

### 语料外发现十三：新增「长片段逐字重复」规则（v1.1）

紧接着收到一份 739 字的**仙侠词穷型打斗样本**（风格与上一份截然相反）。

判定 **58.77 → 61.91 分「偏高」**，抓到了。命中的是典型 LLM 特征：
套话 4.06/千字（"仿佛"×3）、比喻模板 10.8/千字、总结句 4.06/千字
（"她知道"×2、"他知道"×1）、句长 cv 仅 0.262、单行段 0%。

**同一份工具，上一份判 9.73（漏检），这一份判 61.9（命中）**——差别不在工具有没有坏，
而在两份文本离"典型 LLM 写法"有多远：

| | 文学向样本（漏检） | 词穷型样本（命中） |
|---|---|---|
| 句长 cv | 0.821 | **0.262** |
| 段长 cv | 0.784 | **0.264** |
| 单行段占比 | 68.2% | **0.0%** |
| 套话 | 1.97 | 4.06 |
| 比喻模板 | 0 次 | **10.8/千字** |

#### 这次新增的一条规则

检查时注意到一个之前没有度量的现象：这份 AI 文本**逐字重复自己的描述**——
「眼神坚定」出现 3 次、「整个虚空都在颤抖着」2 次、「震耳欲聋」2 次、「挥剑迎击」2 次。
人类写手重复意思时会换词，模型不会。

于是测了「5 字片段出现 ≥2 次的超额重复密度」：

| 样本 | 密度（/千字） |
|---|---|
| 打斗（疑似 AI） | **28.42** |
| ai_xianxia_romance_02 | **14.45** |
| ai_urban_revenge_01 | 1.54 |
| ambiguous_ai_system_01 | 2.44 |
| 人写·市井 | 0.00 |
| 人写·系统流 | 1.57 |
| 人写·武侠文学向 | 4.23 |
| **三份人写文本合并（1883 字）** | **3.72** |

长度效应也做了控制实验（**必须用不同文本拼接**，用同一段重复拼接测的是"复制"不是"长文本"）：
人写 538→1174→1883 字，密度 0→0.85→3.72（缓慢上升）；
AI 651→1412→2233 字，密度 1.54→17.00→17.02（迅速升高）。

新增规则 `RHE_PHRASE_REPEAT`，阈值 **15/千字**（故意定高，只抓极端重复，因为该指标随长度上升）。
实测：只在本份打斗文本上命中（+2.06 分），**全部人写样本与其余 AI 样本都不受影响**。

#### 但这条规则**不能**解决上一次的漏检

那份文学向样本的风险分不变（仍是 9.73）。它不重复自己的话，所以这条规则对它无效。
**上一份漏检依然存在，没有修复**——这次只是补上了一个独立的、有效的信号。

**诚实结论**：现在工具对"典型 LLM 输出"的检出更完整了，
但对"高质量、刻意避免套话"的 AI 文本仍然无能为力。两件事不能混为一谈。

### 语料外发现十四：仪表盘几何 bug + 计分低估（v1.2 修正）

用户反馈两件事，都成立。

#### ① 分数进橙色档后仪表盘画崩了

根因是 SVG 弧线的 `large-arc-flag` 判断写错了：

```python
large = 1 if (f1 - f0) > 0.5 else 0     # 错
```

仪表盘是**半圆**，f 是半圆的比例，所以弧的角度跨度 = (f1-f0)×180°，
最大就是 180°，**永远达不到"大弧"（>180°）的条件**。正确值恒为 0。

写成 `> 0.5`（把 90° 当成大弧分界）后，跨度超过 90° 的弧会被理解成"绕另一边画"——
于是 **分数 >50 时红色弧跑到了下半圈**，而 <50 分时碰巧正确。
所以这个 bug 只在"橙色及以上"才显形，正好是用户看到的现象。

修正：`large = 0`（恒定），并在注释里写清为什么不能是别的值。

#### ② 「特别明显的 AI 只有 59–62 分」——计分确实低估了

用户的原话是「特别明显的AI，也只有百分之五六十的概率」。查下来这是**设计缺陷**，不是调参问题：

| 样本 | 证据总分 S | 命中的维度数 | 旧风险 |
|---|---|---|---|
| 明显 AI·打斗（8 条证据） | 25.10 | **4** | 62 |
| 典型 AI·都市（3 条证据） | 25.14 | **2** | 62 |

**两份文本的证据总量几乎相同（25.10 vs 25.14），所以给了同一个分数。**
但常识上「8 条证据横跨 5 个维度」比「3 条全挤在一个维度」可信得多：
不同维度的特征是互相独立的，**同时出现才说明"系统性"**；集中在一个维度可能只是某种写作习惯被反复命中。

修正：加入**证据多样性加成** + 把饱和常数 K 从 26 调到 22。

```
证据多样性 = 1 + 0.20 × min(有实质贡献(≥1.5分)的维度数 - 2, 3)
总风险     = 100 × (1 - e^(-S × 多样性 / 22)) - 0.30 × 人味证据强度
```

**这一项只加成、不削减**：维度数 ≤2 时取 1.0，分数完全不变，
避免把本来就轻的证据压得更轻。

#### 校准后的全表

| 样本 | S | 维度 | 风险 | 档位 |
|---|---|---|---|---|
| 人写·市井 | 0.08 | 0 | 0.0 | 极低 |
| 人写·系统流 | 0.72 | 0 | 0.0 | 极低 |
| 人写·武侠文学向 | 1.15 | 0 | 4.8 | 极低 |
| 碎片化 AI | 13.26 | 1 | 45.3 | 中等 |
| 典型 AI·都市 | 25.14 | 2 | **68.1** | 偏高 |
| 高浓度 AI·仙侠言情 | 34.12 | 3 | **84.5** | 极高 |
| 明显 AI·词穷型打斗样本 | 25.10 | **4** | **79.8** | 极高 |

人写样本**一个都没动**（仍是 0–4.8），AI 样本全部上移到位。

**注意**：那份文学向样本（确认 AI、漏检）的 S 只有约 2 分、0 个维度，
分数仍在 10 左右，**依然是「极低」**——这次调参没有、也不该改变那次漏检。
多样性加成解决的是"证据够多但分数偏低"，不是"证据根本抓不到"。

### 语料外发现十五：题材自适应对词表类规则从未生效（v1.2 修正）

用一份 2081 字的**高武系统流**章节实测，风险 **37.76「中等」**，
唯一实质证据是 `LEX_CLICHE`（套话 3.36/千字，基线 1.2）。

查命中词：`仿佛×2、微微×2、一股、轻轻、不由自主地`——**这些在玄幻/高武里是正常用词**。
于是去查题材系数有没有生效，发现两个叠加的问题：

#### ① `PatternRule` 根本没读 `GENRE_ADJUST`

题材系数只写在 `ThresholdRule.evaluate()` 里。而 `PatternRule`（**套话、抽象情绪、身体反应、
书面连接词、比喻、排比**——恰恰是最依赖题材的那批词表规则）直接用了裸基线：

```python
base = self.baseline_per_k        # 旧：没有题材系数
```

也就是说，**"题材自适应"从上线起就对词表类规则完全失效**。
文档里写着"只放宽、不收紧"，代码里只是阈值类规则遵守了。

#### ② 已生效的那些，有两项方向写反了

系数统一按 `基线 × 系数` 计算，但两类规则方向相反：

| 规则方向 | 语义 | 放宽该用 |
|---|---|---|
| high（越大越可疑，如套话密度） | 系数乘在**基线**上 | **>1**（抬高基线） |
| low（越小越可疑，如句长变异系数） | 系数乘在**阈值**上 | **<1**（降低阈值） |

`xianxia` 的 `RHE_SIMILE: 0.70`、`wuxia: 0.80` 本意是"仙侠比喻多，放宽一点"，
但 0.70 < 1 在 high 方向上是**收紧**。已改为 `1.40` / `1.30`。
另外 `LEX_IDIOM` 这条规则早就不存在了，是残留的死键，已删除。

#### 修正后的 GENRE_ADJUST

| 题材 | 调整 |
|---|---|
| system 系统/高武 | RHY_SENT_CV 0.70、STR_PARA_TAIL 1.80、RHY_SENT_UNIFORM 0.70、**LEX_CLICHE 1.20** |
| xianxia 仙侠 | PUNCT_ENTROPY 0.80、**RHE_SIMILE 1.40**、**LEX_CLICHE 1.50** |
| wuxia 武侠 | PUNCT_ENTROPY 0.85、**RHE_SIMILE 1.30**、**LEX_CLICHE 1.40** |
| ancient_romance 古言 | **LEX_CLICHE 1.50**、PUNCT_ENTROPY 0.85 |
| suspense 悬疑 | **LEX_EMOTION 1.30**（原 `EMO_ABSTRACT` 是失效键）|

**影响**：本次文本 37.76 → **31.73（偏低）**。其余样本分数不变——
因为强信号的超额倍数本就封顶在 3，抬高基线不会降低它们的得分。
这正是想要的行为：**题材放宽只救边缘案例，不动铁证。**

#### 顺带补的噪声模式

文本里有「排名更是**是**五百序列之后」——重复虚词，典型输入错误。
原噪声规则只认「三连重复字」和「重复的的」，漏了这类。
已补：`(是|的|了|在|就|也|不|有|和|与|而|但|却|都|还|又|太|更|最|我|你|他|她|它|这|那)\1`
（**只限虚词与高频功能字，不含「慢慢／渐渐／轻轻」这类正常叠词**）。

### 语料外发现十六：极端信号被「封顶」削平（v1.3 修正）

用户提出：**某一项信号特别强烈时，应该临时提高它的权重，但不污染规则本身的判断力。**

这个意见指向一个真实的设计代价。原来的计分是：

```
超额分 = min(超额倍数 - 1, 3)
```

封顶 3 倍的理由是"防止单一极端值主导结论"。但代价是：
**「套话密度是基线的 4 倍」和「19 倍」拿到一模一样的分数。**

19 倍意味着什么？真人网文的套话密度通常在 1.2/千字以下，
写到 22/千字相当于每千字里出现二十多个"仿佛/一丝/微微"——**这是不可能自然发生的**。
把它和 4 倍同等对待，等于主动放弃最强的那类证据。

#### 修正：超额 >4 倍时给对数加成

```
超额分   = min(超额倍数 - 1, 3)                      # 不变
极端加成 = min(0.8 × log2(超额倍数 / 4), 1.5)        # 新增，仅当超额 >4
```

| 超额倍数 | 旧分 | 新分 |
|---|---|---|
| 2.0 | 1.00 | 1.00 |
| 4.0 | 3.00 | 3.00 |
| **6.0** | 3.00 | **3.47** |
| **12.0** | 3.00 | **4.27** |
| **19.0** | 3.00 | **4.50** |
| 30.0 | 3.00 | 4.50（封顶）|

用**对数**而不是线性，是因为要保留"缓慢上升"的性质——否则极端值会再次主导。
加成上限 +1.5（即最多比原分多 50%），且**只作用于本次计分**：
规则的严重度、可信度、基线一个都没动，`GENRE_ADJUST`、阈值、词表全部不变。
这正是用户要求的「临时提高权重，不污染判断力」。

#### 影响

| 样本 | 旧风险 | 新风险 | 档位变化 |
|---|---|---|---|
| 人写·市井 / 系统流 / 武侠 | 0 / 0 / 4.8 | **0 / 0 / 4.8** | 无变化 |
| 碎片化 AI | 45.3 | 51.5 | 中等（不变）|
| 典型 AI·都市（套话 21.5≈18倍） | 68.1 | **77.2** | 偏高 → 极高 |
| 高浓度 AI·仙侠言情（套话 22.3≈19倍） | 84.5 | **90.8** | 极高（不变）|
| 明显 AI·词穷型打斗样本 | 79.8 | **72.2** | 极高（不变）|

**人写样本一个都没动**——因为人写的超额倍数普遍在 4 倍以内，压根进不了加成区间。
这就是这个机制安全的原因：它只奖励"人类不可能达到的密度"。

#### 但它解决不了上一份的疑点

用户同时认为「觉醒序列0」那份 AI 含量也应该很高（当前判 31.7 偏低）。
查了它的各项超额：套话 2.33 倍、总结词 1.60 倍、省略号 1.56 倍——**全部在 4 倍以内**，
所以这条机制对它**没有帮助**。

顺手试了两个新指标，**都没有区分度**，没有采纳：

| 指标 | 人写·系统流 | 碎片化 AI | 纯 AI 样本 |
|---|---|---|---|
| 数字密度（/千字） | 3.14 | 7.31 | **0.00** |
| 面板密（【】/千字） | 7.86 | 4.87 | **0.00** |

数字和系统面板只反映**题材**（是不是系统流），不反映**作者**——
纯 AI 的都市/仙侠样本里一个数字都没有。这类"看起来很像 AI"的特征，又一次证明是题材特征。

**「觉醒序列0」那份的 AI 感，来自结构层面（连续三段解释设定数值、信息密度突然抬升），
不是任何词表或统计量能抓的。** 这一点必须如实说明，不能靠调参糊过去。

### 语料外发现十七：权重平均化（v1.3 修正）

用户指出：**"有的维度明显能确定是 AI，但因为和次要维度的权重相同，导致明显的 AI 特征并没有提高评分。"**

复盘了全部规则的有效权重（严重度 × 可信度），问题很清楚：

| 规则 | 旧有效权重 | 实测可靠性 |
|---|---|---|
| LEX_CLICHE 套话 | **4.40** | ✅ 人写 0/千字 vs AI 22/千字 |
| RHY_SENT_CV 句长均匀 | **2.40** | ❌ 人写武侠实测 0.415（低于阈值 0.45）→ 误报 |
| RHE_SIMILE 比喻模板 | **1.98** | ✅ 人写 0–3 vs AI 10.8/千字 |
| PUNCT_ENTROPY 标点熵 | **0.90** | ❌ 我自己在文档里写过"零区分度" |

**两个问题同时存在**：
1. 权重跨度只有 4.9 倍，强信号和弱启发式挤在一起；
2. **排序是错的**——会误报的 `RHY_SENT_CV`（2.40）竟然高于已证实的 `RHE_SIMILE`（1.98）。

后果就是用户说的"摊平"：一条"套话密度 19 倍"的压倒性证据，分给它的权重和一条纯排版启发式差不多。

#### 修正：按实测区分度分三档

```
档位系数 = A级 2.0 ｜ B级 1.0 ｜ C级 0.4
```

| 档位 | 判据 | 规则 |
|---|---|---|
| **A** | 实测能区分人写与 AI，几乎可作确定性证据 | 套话、逐字重复、总结词、对偶模板、比喻模板、段末升华 |
| **B** | 有效性中等，需与其它信号并发 | 情绪命名、身体库存、标注单调、对白乒乓、五感偏视觉、标点集中度 |
| **C** | 受长度/题材干扰大，**实测出现过误报或零区分度** | 句长均匀度、段间距离、单行段、标点熵、用字丰富度、对白占比 |

分档依据全部来自本文档的实测记录，不是主观感觉。写在 `rules.py` 的 `TIER_MAP` 注释里，可逐条复核。

#### 连带发现：密度会被短文本放大

提高 A 档权重后，人写对白样本被判成 46.5「中等」——**误报**。
查原因：531 字的稿子里只有 2–3 个「仿佛/一股」，密度却算到 5.6/千字，
看起来"远超基线"，其实只是三个自然用词被短文本放大了。

修正：词表类规则加**最低命中数**门槛——短文本至少 4 次，长文本按每千字 2 次递增。
超过密度基线但命中次数太少时，不计分（写进"未评分规则"并说明原因）。

#### 校准后

| 样本 | 旧 | 新 |
|---|---|---|
| 人写·市井 / 系统流 / 武侠 | 0 / 0 / 4.8 | **0 / 0 / 1.8** |
| 人写·双人对白流（531 字） | 26.4 | **0.0**（密度虚高被拦下）|
| 碎片化 AI | 51.5 | **76.3** |
| 典型 AI·都市 | 77.2 | **93.5** |
| 高浓度 AI·仙侠言情 | 86.2 | **97.7** |

**权重跨度 4.9 倍 → 24 倍**：一条 A 级强信号（8.80）现在是 C 级启发式（0.36）的 **24 倍**。
人写样本反而更低了（弱启发式不再抬高它们），AI 样本显著更高。**两个方向同时改善。**

### 实测结果（v1.0.0，含对话流误报修正后）

| 样本 | 字数 | 风险 | 区间 | 档位 | 人味证据 |
|---|---|---|---|---|---|
| human_urban_daily_01 | 538 | 0.0 | 0–41 | 极低 | 23.8 |
| human_system_cultivation_01 | 636 | 0.0 | 0–41 | 极低 | 38.3 |
| edge_human_wuxia_literary_01 | 709 | 0.3 | 0–39 | 极低 | 1.0 |
| ambiguous_ai_system_01 | 821 | 40.5 | 0–82 | 中等 | 0.0 |
| ai_urban_revenge_01 | 651 | 63.2 | 25–95 | 偏高 | 0.0 |
| ai_xianxia_romance_02 | 761 | 73.1 | 38–95 | 极高 | 0.0 |

**通过线**（`scripts/selftest.py` 内置）：
- 人写样本必须全部落在 **< 40**（硬要求，误报是致命的）
- AI 样本必须落在 **≥ 56**
- 碎片化 AI 样本必须落在 **36–70**（检出但不得声称极高）

### 语料外发现：对话流误报（v1.0.0 修正）

用一段**用户提供的**双人对白网文片段（518 字，对白占比 38.6%）实测时，
发现了一个语料集没覆盖到的系统性误报：

- 初判风险 **45.3（中等）**，其中最大单项是 `RHY_PARA_HEAD`（7.17 分）；
- 诊断命中位置后发现，反复出现的"页首两字"全部是**角色名**——
  段落交替以两个角色名开头；
- 双人对白场景里，段落交替以两个角色名开头是**人类写对话的正常方式**，
  不是"机械重复"。检测器把一个正常的叙事结构当成了 AI 痕迹；
- 该误报把这段文本从「偏低」推到了「中等」，**正好踩在会让作者慌的档位上**。

修正：新增 `detect_names()`，从文本自身识别高频人名/专名并在该规则中排除
（判据见 `rule-catalog.md`；带"识别出 >3 个专名则放弃排除"的保险丝）。
修正后同一片段风险 **29.4（偏低）**。

**这个案例值得记住的地方**：
1. 语料集覆盖不到的场景，真实用户一测就暴露了——**自测语料永远不够**；
2. 误报的方向是**把正常的叙事结构误读为统计规律**，这是本工具最容易犯的错，
   比"漏掉某条 AI 痕迹"严重得多；
3. 修正没有损害检出能力（两份 AI 样本 63.2 / 73.1 基本不变），
   但让碎片化 AI 样本从 49.7 降到 40.5——**这是诚实的代价**：
   去掉假阳性驱动力之后，那些真样本确实更难检了。

### 从实测得到的诚实结论

1. **词汇与话语层信号区分度极好**：套话密度在人写样本上是 **0.00/千字**，
   在 AI 样本上是 **9.7–22.3/千字**——差一到两个数量级，几乎不需要阈值判断。

2. **节奏层信号比预期弱**：原以为句长变异系数是"最强指纹"，
   实测中人写文学向样本的 cv 只有 **0.415**，低于 AI 样本（0.64–0.72）。
   这说明**"句子整齐 = AI"这条经验法则在小样本上不成立**。
   已把相关规则的严重度从 5 降到 4、可信度从 0.72 降到 0.60，并加了 ≥30 句的前置条件。

3. **人味信号需要区分度，不是数量**：
   初版人味词表含「可」「老」「整」「草」「滚」等单字与高频通用词，
   导致 AI 样本也拿到人味分（最高 +21 分），**减项变成了噪声源**。
   修正后只保留有区分度的词条（口语、俚语、方言、明确的粗话）。

4. **有些 AI 文本就是检不出来**：`ambiguous_ai_system_01` 是标准 AI 生成的系统流，
   但它碎片化、对白多、短段多，把统计特征都稀释了，最终落在"中等"。
   **这是诚实的失败**，报告正确地给出了"检出但不可靠"的结论，
   而不是硬把它推到"极高"。这一点已写进报告的不确定性章节。

5. **区间宽度反映真实不确定性**：人写样本区间 `0–44`，AI 样本区间 `39–95`。
   两者有重叠——这是事实，不该被掩盖。区间越宽说明结论越软，
   报告会直说"建议人工复核"。

## 2. 与商业检测器的横向对比

**没有做过横向对比，也建议不要做单点对比。** 理由：

- 朱雀等服务不公开 API 与判据，无法批量评测；
- 它们的结果随平台模型更新而变，单次对比没有信息量；
- 更要命的是**没有 ground truth**：我的自测语料是我自己写的，
  用它来"证明"工具准确，等于用同一批数据训练和测试。

**诚实的说法**：本工具没有在大规模标注语料上验证过。
它的基线来自小规模自建语料加工程经验。
因此它输出**区间**而非定值、强调**可复核**而非权威。

用户问"准不准"时的正确回答见 `SKILL.md` §6。

## 3. 怎么提升准确率

### 3.1 用作者自己的作品建基线（最有效的办法）

单作者基线比通用基线准得多。做法：

```powershell
$py = "python"   # 任意 Python 3.9+，无第三方依赖
# 1) 取该作者 AI 出现之前写的、平台没有判定过的旧稿（建议 ≥5 章，≥1.5 万字）
# 2) 逐章跑检测，收集量化指标
& $py "<技能目录>\scripts\analyze.py" "旧稿合集.txt" --out "baseline" --format json
```

然后从 `baseline/*.report.json` 里读 `features`，取各指标的**中位数与四分位**，
替换 `data/lexicon_ai.json` 里对应的 `_baseline_per_k`，以及 `rules.py` 里
`ThresholdRule` 的 `threshold` 参数。

**原则**：
- 用**作者自己的**基线，而不是全站统计。作者的个人习惯差异远大于 AI/人的差异。
- 基线要取**中位数**而不是均值（极端章节会污染均值）。
- 至少 5 章才有统计意义；少于 5 章时不要自建基线。

### 3.2 按题材与平台调参

不同题材的正常值差距极大。`rules.py` 的 `GENRE_ADJUST` 表可以直接加条目。
**必须遵守**：调整值只允许 ≥1.0（放宽），不允许 <1.0（收紧）。

### 3.3 扩充词表

`data/lexicon_ai.json` 是纯数据文件，可以直接改：

```json
"artistic_cliche": {
  "_baseline_per_k": 1.2,
  "words": ["仿佛", "宛如", "...你的新词..."]
}
```

**加词的两条纪律**：
1. **必须跑 `selftest.py`**，确认人写样本仍然落在中低档；
2. 单字词与高频通用词（可/的/了/老/整）**一律不要加**——
   它们会同时命中人写和 AI 文本，等于给减项注水，反而降低区分度。

### 3.4 积累"判决 + 真实结果"的反馈

如果知道某段文本的**真实来源**（作者确认自己写的 / 作者承认是 AI 生成的），
把它加进 `corpus/` 并相应更新 `selftest.py` 的 `EXPECT` 表。
语料攒到 30 份以上时，可以：

- 统计各规则的真阳性率 / 假阳性率，删掉假阳性率高的规则；
- 重新拟合分类归一常数与总风险的 K 值（当前 K=26 是小样本手工调出的）。

**这是唯一能真正提升准确率的路径**——不是调公式，是攒标注数据。

## 4. 已知局限（必须如实告知）

1. **基线不硬**：见 §2。
2. **改写会低估**：AI 文本经人工改写后典型痕迹被稀释，本工具会低估。
   改写越彻底，低估越严重，极端情况下会判为"极低"。
3. **程式化题材可能高估**：系统流、签到流人写也句式重复。已按题材放宽，无法完全排除。
4. **短样本不可靠**：< 1000 字区间强制放宽；< 300 字拒绝给结论。
5. **不做创作主体认定**：本工具描述的是**文本特征**，不是**创作过程**。
   一段文本"具有 AI 特征"不等于"由 AI 生成"——人也可以写得像 AI
   （刻意模仿、套模板、用写作软件辅助）。
6. **无对抗鲁棒性保证**：有人刻意规避（加口语、打乱句长、插错别字）时，
   本工具会失效。这不是缺陷，是 AI 检测的固有限制。
